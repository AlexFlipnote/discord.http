discord_http.backend module¶

class discord_http.backend.DiscordHTTP(*, client)¶

Bases: Application

Serves as the fundamental HTTP server for Discord Interactions.

We recommend to not touch this class, unless you know what you’re doing

Parameters:

client (Client)

signature_max_age: float | None = 300.0¶

How far the signed timestamp of a request may be from the local clock, in seconds.

A request older than this is refused even with a valid signature, so a captured request can’t be sent again later. The default leaves plenty of room for a drifting system clock, None turns the check off.

bot: Client¶

The bot instance that is using this HTTP server.

debug_events: bool¶

Whether to dispatch debug events for interactions received, defaults to False.

host: str | None¶

The host the HTTP server listens on, None until it is started.

port: int | None¶

The port the HTTP server listens on, None until it is started.

interaction_path: str¶

The path interactions are received on, always starting with a slash.

verify_key: Ed25519PublicKey | None¶

The verify key used to validate incoming requests, if not set, it will try to fetch from the bot’s public key.

async handle_gateway_interaction(data, *, replayed=False) → None¶

Handles an interaction received over the gateway, used when the application has no interactions endpoint URL.

It runs the exact same way as an HTTP interaction, but the response is sent to Discord’s callback endpoint instead of being the HTTP response body.

Parameters:

  • data (dict) – The raw interaction payload from INTERACTION_CREATE

  • replayed (bool) – Whether the interaction was replayed by Discord after a resume, expired ones are skipped instead of running the command

Return type:

None

update([E, ]**F) → None.  Update D from mapping/iterable E and F.¶
If E present and has a .keys() method, does:

for k in E.keys(): D[k] = E[k]

If E present and lacks .keys() method, does:

for (k, v) in E: D[k] = v

In either case, this is followed by:

for k, v in F.items(): D[k] = v
